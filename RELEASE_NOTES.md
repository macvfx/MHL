# Release Notes

([MHL Verify changelog](MHL_VERIFY_CHANGELOG.md), per-app READMEs and user guides).

## Media Trust Tools suite (CopyTrust, Drop Verify, Folder Copy Compare, mhl-tool)

| Version | Date | Summary |
|---|---|---|
| **CopyTrust 2.7.2** *(public beta prerelease, Build 32)* | 2026-08-09 | **A card's artifacts could stop dead and spin forever.** In a two-card test the first card's contact sheet wrote one destination's PDF, got partway through the second, and then that card produced nothing for the rest of the session — the row sat on its last message, its proxies sat on "Queued…", and Rebuild All was the only way out. The cause was a metadata subprocess whose output pipes were left undrained, so it could block on a full buffer and neither its own deadline nor the outer timeout could unwedge it; it is now drained continuously and killed if it hangs. A **stall watchdog** backs that up: any artifact silent for five minutes is failed with a per-artifact **Retry**, so nothing spins indefinitely again. **Proxy progress** now shows the work left across the whole run — `7 of 10 · A001 → RAID 01 · 15%` — instead of a per-destination count and a wall of encoder detail. **End Session** no longer did nothing while an artifact was wedged — it waited on a task that could never finish; the wait is now bounded by progress, and while artifacts run the button offers End Now or Wait. **The menu bar** no longer reads as finished while proxies encode: it shows which cards are safe to eject and what is still running. **Session Health and the receipt text** grow with the window instead of sitting in fixed scroll boxes. Includes Build 31. **CopyTrust only.** |
| **CopyTrust 2.7.2** *(public beta prerelease, Build 31)* | 2026-08-09 | **Every card in a multi-card run is visible, and the counts add up.** Staging two cards showed only the one copying right now; the queue row now lists both, each with its own bar and status, and its progress bar covers the whole run instead of filling to 100% at the end of the first card. File counts are **file copies** — one per file per destination — so a 47-file card going to two destinations counts toward 94, not 47, and the menu bar agrees with the activity log. The menu bar also shows which card is running and a second bar for all of them. **CopyTrust only; Drop Verify stays at Build 15, Folder Copy Compare at Build 14.** |
| **Drop Verify 2.7.2** *(public beta prerelease, Build 15)* | 2026-08-08 | **The proxy progress bar no longer sweeps back and forth.** Proxy encoding is the longest phase of a run and had the least readable progress: the artifact phase reported only a message, so the bar fell through to its indeterminate branch for the whole phase, even though ffmpeg's own per-clip percent had been driving the status text since Build 8. That percent now drives the bar too — each clip owns one slice, filled by its encode percent and closed out when the clip finishes, so the bar only moves left to right. A clip whose duration ffmpeg cannot determine holds at the start of its slice and steps forward whole rather than guessing at a position inside it, and a failed clip still closes its slice. **Shipped in the 2.7.2+30 pre-release alongside CopyTrust Build 30 and, for the first time, MHL Verify 2.6.0.** |
| **CopyTrust 2.7.2** *(public beta prerelease, Build 30)* | 2026-08-08 | **One blue action button.** Colour now says what a control does: blue is the action and there is exactly one on screen — `Start`; orange is a mode change that alters what a run will do but starts nothing; neutral is optional or later. The `Simultaneously` / `In series` switch is now **orange**, matching the Card/Folder switch — it carried no tint, so it inherited the blue accent and its selected segment read as the button to press when it only decides what `Start` will do. The Queued Sessions panel **loses its own `Queue Current Session` button**: it was styled as the primary action while explicitly not starting a copy, and it was a strict duplicate of the action-bar button, which remains — the panel now carries the explanation alone, saying where the control is. The Help sheet's topic picker stays blue, being modal navigation rather than a mode. **Drop Verify and Folder Copy Compare stay at Build 14; Build 30 touches CopyTrust only.** |
| **CopyTrust 2.7.2** *(public beta prerelease, Build 29)* | 2026-08-08 | **One Copy switch, one Start button.** With two or more destinations a segmented **Copy** switch chooses **Simultaneously** (every destination at once, the source read once per destination) or **In series** (each stop's verified output feeds the next, the source read once), and one button — always labelled **Start** — runs it. This replaces `Queue Relay Chain`, which appeared three times, started nothing, and left the operator to find `Start Queue` elsewhere: because the pre-copy review fires when a copy starts, a relay chain built that way ran with **no review at all**. Start now builds and starts the chain in one action, so the review always appears. The four contextual Start labels are gone with it. **Fixed: every relay copy crashed just after the first stop finished** — the immutable workflow plan exported into each destination's receipts folder was written with a file-write option pair macOS rejects outright, taking the app down with files, MHL and a completed manifest already safely on disk but the queue not yet updated. **Interrupted jobs now recover:** on launch a job still recorded as running is checked against the destination's own manifests, so a copy that had actually finished comes back complete and the chain carries on from the next stop instead of reopening stuck. **New relay chains** put Archive to P5 on the first stop and proxies on the last — camera archive first, editing storage last. **Drop Verify and Folder Copy Compare are rebuilt at 2.7.2 Build 14 alongside this release for suite alignment only** — neither has changed functionally since Drop Verify Build 8. Testing notes: [TEST_NOTES_v2.7.2.md](TEST_NOTES_v2.7.2.md). |
| **CopyTrust 2.7.2 / Drop Verify 2.7.2 / Folder Copy Compare 2.7.2** *(public beta prerelease)* | 2026-08-07 | **Drop Verify gains proxy media**, using the same generator, codecs (HEVC / H.264), sizes (12.5 / 25 / 50%) and Final Cut folder layout as CopyTrust — off by default, with per-clip progress (percentage, speed, ETA) and its own JSON receipt, readable summary and encode log. Three rules govern it: only files that passed verification get a proxy (so enabling proxies hashes the media even when MHL is off), proxies are written beside the media and are never copied to the export folder because they are footage rather than evidence, and a clip that fails to encode is reported and skipped without changing the verified result. **Sessions now record the operator:** `SessionManifest` carried hostname, macOS and tool version but had no operator field in either app; both now write it, and the operator name defaults to the macOS account when blank so receipts are never anonymous. **Fixes:** "Open Artifacts" did nothing on a proxy-only run; the proxy row linked to one arbitrary movie rather than the folder; the session manifest was never exported on any run; proxies were missing from the history CSV; and the artifact-URL fallback matched exported files by substring, which could report an artifact that was never made. |
| **CopyTrust 2.7.1** *(public prerelease, Build 14)* | 2026-08-07 | **Operator presets:** save every Card **and** Folder setting under one name and load it back in a single action, from a Preset menu beside the copy-mode picker. A dot marks settings changed since loading; "Update … from Current Settings" re-captures in place. A preset carries policy, not environment — both mode profiles plus confirm-before-copy, external codecs, ExifTool, the codec extension lists, receipt export and notifications. Destinations, tool paths, P5 credentials, operator name and appearance are deliberately excluded so a preset stays portable between machines. Shared presets deploy read-only from `/Users/Shared/CopyTrust/Presets`, a path that exists on a fresh Mac and needs no user account, so presets can be placed by script or MDM before an operator's first launch; personal saves go to Application Support so re-deploying can never clobber them. Loading a preset never changes destinations — it names the destination set it expects and says whether that set exists on this Mac. **Naming:** "preset" previously meant two different features, so the Card/Folder toggle is now the copy **mode** and destination presets are **Destination Sets**. |
| **CopyTrust 2.7.0** *(public prerelease, Build 12)* | 2026-08-01 | **Proxy rotation and color correctness:** CopyTrust probes each delivered original before encoding, calculates proxy dimensions from displayed orientation, carries reported color range/primaries/transfer/matrix into the encode, and records encoded/display dimensions, rotation, and source/proxy color evidence. Missing source color fields remain N/A instead of being claimed as preserved. Sorted-destination provenance fallback now records the actual active sort configuration. Includes Build 11 workflow review and immutable relay evidence plus Build 10 per-destination P5/proxy routing. |
| **CopyTrust 2.7.0** *(public prerelease, Build 10)* | 2026-07-31 | **Relay-chain P5 pre-check and per-destination proxies:** P5 selection is evaluated across every queued relay stop, eliminating the false no-destination warning when a later stop is selected. Each destination now has an independent **Create proxies** checkbox, so proxy and P5 routing can target the same destination, different destinations, or both. Presets and queued sessions preserve proxy choices; older saved data remains proxy-enabled by default. Includes the Build 9 proxy-result correction, guarded P5 archive workflow, queue hardening, and privacy-safe Sentry baseline. |
| **CopyTrust 2.6.0 / Drop Verify 2.6.0 / Folder Copy Compare 2.6.0** *(public beta prerelease, Build 1)* | 2026-07-28 | **CopyTrust proxy media beta:** optional H.264 High or HEVC Main 10 MOV proxies at 12.5%, 25%, or 50%; optional dated `Final Cut Proxy Media` layout; exact original basenames for relinking; live clip/total, percentage, speed, and ETA; JSON/TXT/LOG evidence comparing original and proxy technical properties. The pre-copy confirmation and session log explicitly record Proxy Off or the selected settings. Real automated encodes cover MOV and MXF; other inputs depend on packaged ffmpeg decoder support. **Package safety:** CopyTrust and Drop Verify put receipt and proxy folders beside `.fcpbundle` and other macOS package roots rather than inside them. |
| **CopyTrust 2.5.5 / Drop Verify 2.5.5** *(testing, Build 1)* | 2026-07-24 | Field-test follow-up. **CopyTrust:** a copy now shows a **mode-confirmation** summary (mode, verification level, artifacts, destination sort, contact-sheet split) before it starts, so an accidental Folder-mode card copy is caught before it runs — shown only on manual/queued starts, never on auto-advance or resume, and toggleable in Settings → Post-Copy → Before Copy. Each copy start also logs a one-line mode summary, and the activity log pane is now resizable (height remembered across launches). **`.sb-*` sandbox temp files** (created by FCP/Motion) are now skipped silently like any other exclusion — no longer listed as transient skips or shown in the Session Health report — with the count noted once in the log. **Drop Verify:** Contact Sheet / Metadata CSV / Project Tree HTML now generate independently with per-artifact status, individual **Retry**, and **Rebuild All**; retry reuses the completed scan/hash and re-exports when configured. |
| **CopyTrust 2.5.4 / Drop Verify 2.5.4** *(testing, Build 6)* | 2026-07-22 | New **Split large contact sheets** setting in both apps (Off / every 250 / 500 / 1,000 files): large cards and folders are written as numbered PDFs (`…_part1of9.pdf`) with a "Part x of y — files a–b" header line instead of one very large PDF. Fixes the large-card contact sheet timeout: the 180 s limit now scales with file count, a timed-out run stops promptly and leaves no orphaned PDFs, and with auto-open enabled a multi-part result is revealed in Finder instead of opening every PDF. Build 2 (field-test feedback): disabled artifacts log an explicit "disabled in <mode> mode settings — skipped" line instead of silence; contact sheet generation logs heartbeat progress (metadata pass + per-part written lines) and the style/split/timeout in effect; per-mode Post-Copy controls refresh immediately; HTML tree artifacts renamed `tree_…` in both apps (legacy `dropverify_tree_…` still recognized). Build 3: the live activity log gains a copy heartbeat line every ~5 s (percent, file copies, bytes, speed), and the menu bar shows an orange verification bar with its own percentage during post-copy verify instead of a full copy bar. Build 4: fixes a deadlock where contact sheets on proxy (LRF) / MXF-heavy cards hung forever (blocking subprocess read that also defeated the timeout, plus a redundant preview audit pass) — subprocesses are now killable (SIGTERM→SIGKILL) with non-blocking stderr, and the audit is skipped when placeholders are shown / timeout-wrapped when hidden; Contact Sheet / EXIF CSV / HTML Tree each get their own status and Retry. Build 5: artifact filenames reconciled to a subject-first scheme in both apps — `<subject>_<stamp>_<app>_<type>.<ext>` for contact sheet / EXIF CSV / HTML tree (sorts by subject, keeps creator + type in the name); MHL keeps its industry-style name and receipts are unchanged; discovery/export/retry recognize legacy names. Build 6: fixes the critical Quick-verification regression where a successful copy produced no PDF/CSV/tree because descriptive artifacts incorrectly depended on the hash-only file list. CopyTrust now keeps a separate delivered-file inventory for contact sheet, EXIF CSV, HTML tree, destination sort, retry, and receipt counts without inventing hashes; Quick still writes no MHL. Enabled artifact rows now always reach a terminal state instead of spinning forever. |
